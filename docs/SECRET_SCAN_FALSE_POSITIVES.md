# Reviewed Full-History Secret-Scan False Positives

## Decision

Three redacted Gitleaks findings were reviewed from the private `full-history-secret-scan-redacted` workflow artefact. They were generated by the default `generic-api-key` rule in historical `.commandgate` recovery artefacts.

The findings are not credentials:

1. Commit `98e5ca271d70cb880a8f8a860aaf629f90be3faf`, `.commandgate/recovered-manifest.json`, line 45.
   - The committed file is a recovery-analysis manifest.
   - Its records contain repository paths, encoded/decoded byte counts and SHA-256 file hashes.
   - The finding occurred where a filename was associated with recovered base64 source text.

2. Commit `83408ba15fe3be4ecaf0f08844b079757fb96ad2`, `.commandgate/recovered_apply_command_gate.py.partial`, line 6.
   - The committed file is an interrupted recovery script containing a mapping of repository filenames to recovered encoded source.
   - Two strings on the same historical line were reported under one Gitleaks fingerprint.
   - They were recovered source payloads, not provider API keys, passwords, tokens or active application secrets.

## Allowlist scope

`.gitleaksignore` contains only the exact historical fingerprints shown by the private redacted report. It does not allowlist:

- an entire file path;
- the `generic-api-key` rule;
- a commit generally;
- current or future `.commandgate` content;
- any secret pattern.

Any new finding, including another finding in the same historical files with a different fingerprint, will continue to fail the workflow.

## Review evidence

The commits identify the material as Command Gate recovery analysis. The manifest records SHA-256 integrity values and base64-recovered source fragments. No production credential format or provider identifier was present in the redacted finding metadata.

## Security rule

If a future review reveals that any ignored fingerprint is an actual credential, immediately:

1. remove the fingerprint from `.gitleaksignore`;
2. rotate and revoke the credential;
3. purge or neutralise the historical material where practical;
4. rerun the complete-history scan;
5. record the incident and remediation.
