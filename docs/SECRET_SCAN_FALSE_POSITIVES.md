# Reviewed Full-History Secret-Scan False Positives

## Decision

Four redacted Gitleaks findings have been reviewed from private `full-history-secret-scan-redacted` workflow artefacts. They were generated by the default `generic-api-key` rule and are not credentials.

1. Commit `98e5ca271d70cb880a8f8a860aaf629f90be3faf`, `.commandgate/recovered-manifest.json`, line 45.
   - The committed file is a recovery-analysis manifest.
   - Its records contain repository paths, encoded/decoded byte counts and SHA-256 file hashes.
   - The finding occurred where a filename was associated with recovered base64 source text.

2. Commit `83408ba15fe3be4ecaf0f08844b079757fb96ad2`, `.commandgate/recovered_apply_command_gate.py.partial`, line 6.
   - The committed file is an interrupted recovery script containing a mapping of repository filenames to recovered encoded source.
   - Two strings on the same historical line were reported under one Gitleaks fingerprint.
   - They were recovered source payloads, not provider API keys, passwords, tokens or active application secrets.

3. Commit `515db3b30630214b13b93fcd86bbb281d0a9a2bd`, `backend/tests/inventoryTraceabilityFoundation20260810.test.js`, line 20.
   - The finding was a deterministic `TEST_SECRET` value used only to exercise signed inventory-label verification in the new traceability unit tests.
   - It was committed as test fixture material, not read from any provider, environment, deployment, user account or credential store.
   - The current test constructs equivalent deterministic material at runtime specifically so secret scanners do not confuse test vectors with credentials.
   - The private redacted report identified only this exact historical test fingerprint; no provider identifier or active credential source was present.

## Allowlist scope

`.gitleaksignore` contains only the exact historical fingerprints shown by the private redacted reports. It does not allowlist:

- an entire file path;
- the `generic-api-key` rule;
- a commit generally;
- current or future `.commandgate` or inventory-test content;
- any secret pattern.

Any new finding, including another finding in the same historical files with a different fingerprint, will continue to fail the workflow.

## Review evidence

The Command Gate commits identify their material as recovery analysis. The inventory traceability finding points to a Node test constant named `TEST_SECRET`, used only as deterministic signing material for label-signature tests; the current source constructs that test-only material at runtime. No production credential format, provider identifier, environment-derived secret, or deployment credential was found in the reviewed metadata.

## Security rule

If a future review reveals that any ignored fingerprint is an actual credential, immediately:

1. remove the fingerprint from `.gitleaksignore`;
2. rotate and revoke the credential;
3. purge or neutralise the historical material where practical;
4. rerun the complete-history scan;
5. record the incident and remediation.
